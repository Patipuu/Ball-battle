# BB-03: Audio integration

Date 2026-10-13. HEAD `e0d6935` (BB-01+02). No commit, no push. Every change is in the working tree, waiting for review.

Preconditions checked before any change: HEAD `e0d6935`, only the 50 untracked files in `Assets/Audio` plus the listed out-of-scope items, Unity closed. ## Event → cue

| Event (View side) | Cue | Duck −2.5 dB | Pitch |
|---|---|---|---|
| Button tap (`PixelButton.ClickCue`) | `ui_click` | – | 1 |
| BACK / MENU / NO button, Esc that does something | `ui_back` | – | 1 |
| Blocked card or REROLL | `ui_denied` | – | 1 |
| `RunFlow.CardTaken` (Prepare, start pick, retry pick) | `card_pick` | – | 1 |
| `RunFlow.Rerolled` | `card_reroll` | – | 1 |
| `RunFlow.FightBegan`, `MatchFlow.RoundBegan` | `fight_start` | yes | 1 |
| Arena `MatchEnded`, 0.5 s later (after the KO slow-mo); Run = from ball 0's side | `fight_win` / `fight_lose` | win: yes; lose: no, fight music fades over 0.4 s | 1 |
| `MatchPrepared` with `Run.IsRetry` (retry banner) | `retry_banner` | yes | 1 |
| Summary appears | `run_win` / `run_over` | win: yes; over: no | 1 |
| Summary appears, per green milestone row drawn | `unlock` at 0, 0.25, 0.5 s… | – | 1 |
| `TraitTriggered` second-wind | `second_wind` | yes | 1 |
| `Hit` (A = attacker) | `hit_<attacker weapon>`, else `hit` | yes | 1 ±3% |
| `ProjectileHit` with damage (A = owner: HIVE turret → `hit_rig`, SPARKLER arrow → `hit_volley`) | `hit_<owner weapon>`, else `hit` | yes | 1 ±3% |
| `Parry` / `ProjectileDeflected` / `ShieldBlocked` | `parry` | yes | 1 / 1.3 / 0.8, ±3% |
| `WallBounce` / `BallBounce` / `ObstacleHit` / `ProjectileFired` | `wall` | – | 1 / 0.8 / 0.7–1.2 / 1.7, ±3% |
| `Death` | `death` | yes | 1 |

Dedupe: the same id once per Sim tick (UI cues: once per frame). At most 3 hit cues per tick, different weapons can layer. Music: Menu / Run Title / Versus pick / Settings / Pick weapon / Start pick / Prepare → `music_menu`; fight → `music_battle`; a boss fight per `RunState.IsBossFight` → `music_boss`; Fight result / Summary / Versus result → `music_result`. Equal-power crossfade of 0.6 s; requesting the track already playing does not restart it. Music pitch is always 1. Ducking uses `Time.unscaledDeltaTime` with an injectable clock (`AudioDirector.Clock`).

## Deviations

1. **`docs/design/art/v2_settings.png` does not exist**, so Settings follows the text spec: SETTINGS heading, MUSIC and SFX each with a 10-cell slider (200 px, number on the right), LANGUAGE with EN (selected) / VI boxes, BACK. No screenshot was taken; layout is checked by test only.
2. **No pause screen exists.** The −6 dB pause duck is in place (`AudioDirector.Paused`) but nothing turns it on yet. The gear is only on the menu hub.
3. **No music existed before**, so there was no "stronger drop" to keep. fight_lose / run_over (and fight_win / run_win) fade the fight track out over 0.4 s. The fade only applies to `music_battle` / `music_boss`: on the Summary, `music_result` keeps playing (by then the fight has already ended).
4. **The screen map in the spec does not cover Pick weapon / Start pick / Prepare**, so they use `music_menu` (following the GDD: "Menu / Run Title / Prepare share one loop"). The per-fight result screen uses `music_result`.
5. **Sound moved from FxView to AudioDirector**; volumes and base pitches are kept. Changes: a hit uses the weapon's own clip at pitch 1 ±3% instead of the generic hit with a "heat"-based pitch; the old wall random ±10% is now ±3%; second wind used `parry` and now uses `second_wind`; the generic `win` sound is no longer played (replaced by fight_win / fight_lose; the clip stays in the library).
6. **Versus has no player side**: a round with a winner → `fight_win`, a draw → `fight_lose`.
7. **A deflected shot** sounds as the deflector's weapon, because the Sim makes the deflector its owner.
8. **"Once per Sim tick"** applies to match cues. UI and flow cues are deduped per frame.
9. **Volumes are saved on every step change** while dragging (load, change the two fields, save through the existing `FileSaveStore`). Tests use `MemorySaveStore` only.
10. `PixelInput` has no drag event, so the slider follows `PixelInput.Current` while its button is held. A tap uses the press point (`LastPressNative`).
