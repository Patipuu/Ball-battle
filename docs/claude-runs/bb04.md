**Why WARDEN misses.** Its HP is at the +25% limit (220 → 275).

- HP moved it 86 → 81–84%.
- Faster and deeper closing (first step at 6 s, 12% steps, 45% floor) made no measurable difference (83.7 → 83.2%).
- The remaining Warden values cannot fix it:
  - The warning length does not matter to the bots, which never dodge.
  - The 8 s cadence is promised by the hint.
  - The trait count was not in the tunable list.

The bots beat it as a big random-weapon ball. Shrinking walls hurt both balls alike, and the boss loses most exchanges.

Closing the gap needs a stronger rule, for example:

- damaging walls during the warning, or
- a step that also pushes the player toward the boss.

That is a rule change outside "tune boss values ±25%".

**MAGNET** sits exactly on its 80% upper bound. With about 300 runs per boss the noise is ±3 pp, so a later unrelated change can flip it either way.

## Task 1: Sim

New `Assets/Scripts/Sim/Boss/`:

- `BossTuning.cs`
- `BossRule.cs`: the abstract `BossRule` and the `BossEvent` enum.
- `BossRules.cs`: `BossIds`, `BossRegistry`, and the four rules.
- `MatchSim.Boss.cs`: the MatchSim hooks.

How a boss is attached and run:

- **Attachment.** A boss rule rides on `BallLoadout.Boss`. The Run's enemy generator attaches it through `RunBuild.BossId` when the fight is a boss fight.
- **Matches without a boss** (all Versus, all normal fights) never enter boss code. There is no new state and no new hash input.
- **Timers.** All boss timers read `ActiveTick`, so hit-stop never advances them. The ShellKing and Warden tests check this with an injected hit-stop.
- **Fixed point.** All boss math is Fix (Q16.16). `SimSourceScanTests` passes.

Boss mechanics:

- **SHELL KING**: 150 HP, 0 traits. Cycle warn 30 → ON 180 → OFF 150, first warning at ActiveTick 60.
  - When the shell turns ON it faces the target and stays fixed for that cycle (`Facing`). It covers a `ShellArcDeg` (120°) arc.
  - The arc test uses Fix trig: `dot(contact − centre, facing) ≥ |contact − centre| · cos(arc/2)`.
  - A weapon or projectile hit whose contact point is inside the arc deals 0 and counts as no hit: no weapon growth (`OnHit`), no `HitCount`, no StatChanged, no on-hit hooks, and a shield charge is not used up.
  - Knockback, hit cooldown and hit-stop still apply.
  - Poison, reflect and hazard damage do not go through the hit pipeline, so they ignore the shell.
- **MAGNET**: 200 HP, 0 traits. Cycle 300, first warning at ActiveTick 120: warn 60, pull 45, rest.
  - During the pull, the player gains `MagnetPullPerTick × MatchConfig.MaxSpeed` per tick toward the boss centre, then is clamped to its normal speed cap.
  - The Heavy trait (any level) halves the pull.
- **MIMIC**: 275 HP. The Run layer builds its loadout at fight start: `RunState.Enemy` copies the player's weapon and traits at the same levels. `CreateMatch` therefore copies the final build, including cards picked after the preview.
- **WARDEN**: 275 HP, 2 random traits (as the old fight-8 boss).
  - First step at ActiveTick 360, then every 480. Each step is 12% of the ORIGINAL width/height, down to a 45% floor (4 steps max). There are 60 ticks of warning before each step.
  - The arena is the smaller, per axis, of this and the normal shrink.
  - On a step, balls outside are moved just inside: position only, no bounce, no damage, no event. Any overlap is resolved with the normal `ResolveBallCollisions`, repeated with a re-clamp until nothing overlaps (at most 32 rounds).
  - Obstacles whose centre is now outside are disabled for the rest of the match (`MatchSim.ObstacleActive(k)`), for balls and projectiles.
  - Spike zones follow the current walls at 3/20 (same rule as the normal shrink).

Events and rules version:

- **Events.** There is one new `SimEventType.Boss` with `Variant = BossEvent`: ShellWarn/On/Off, MagnetWarn/Pull/End, MimicCopied (first active tick), WardenWarn/Step.
- A shell-stopped hit is a `Hit` (or `ProjectileHit`) with Value 0 and `Variant = 1`.
- The boss base is unchanged: radius 24 (`RunTuning.BossRadius`).
- **Rules 7 → 8.** Versus and round-robin results are identical (see *Versus proof*).

## Selection and save

How bosses are chosen:

- `Sim/Run/BossSelection.cs` decides the boss per slot once, at `RunState.Start`, and stores it in `RunState.BossIds`.
- The preview, the fight and a retry therefore always agree, and a saved run keeps its bosses.
- **First run on a save** (`RunsPlayed == 0` and no last boss): SHELL KING + MIMIC.
- **Later runs** never repeat the previous run's boss in the same slot (`ProgressData.LastBoss`). With two bosses per slot this means they alternate.
- The seed derive (`RunTuning.Derive(seed, 5000 + slot, 0)`) decides only when no last boss is known: a migrated save, or the bots.
- `RunFlow.ChooseWeapon` calls `BossSelection.Remember` right after `RunState.Start`, before any forced boss.

Save, codex and rewards:

- **Boss Codex:** `ProgressData.BossCodex` holds one `{Id, Met, Defeated}` row per boss. `UnlockRules.Record` fills it from the new `FightRecord.BossId`.
- **Rewards** stay on the slots: winning fight index 3 earns `boss1`, winning fight index 7 earns `boss2`, whichever boss it was. Tested with MAGNET earning boss1.
- **`SaveData.CurrentVersion` 2 → 3.** Old saves follow the existing `SaveMigration` rule:
  - Progress is kept; the in-progress run is dropped, counted as reaching its fight, with the one-time notice.
  - The new fields load empty.
  - `RunSave` stores `BossIds`, `ForcedBossId` and `ForcedBossFight`; `FightRecordSave` stores `BossId`.
  - `RunValidation` rejects a run whose bosses are missing or in the wrong slot.

**`-bbForceBoss <shellking|magnet|mimic|warden>`** (`DebugOptions.ParseForceBoss`):

- Matching ignores case, dashes, underscores and spaces.
- It applies in Run only, through `RunFlow.ForceBossId`; Versus never reads it.
- The boss takes its own slot and the next fight, if that fight is not already a boss fight and not a locked (resumed mid-fight) fight.
- It lives in `RunState.ForcedBossId` and `ForcedBossFight`, never in `BossIds`, so `Remember` never stores it.

## Deviations from the spec

1. **Balance:** WARDEN misses its 35–70% band at 83.2% (see Outcome). MAGNET is at exactly 80.0%.
2. **"Greedy beats it"** is measured per run that met the boss, retry counted. First-try rates are also reported. All first-try rates are inside the bands except WARDEN (79.3%).
3. **Weapon vs boss** uses a proxy, so a 100-seed sample per cell needs no luck to reach fight 8: a Greedy build with greedy card picks before every fight; earlier fights are counted as won at full HP and not simulated; then the real boss fight. Seeds are 10000–10099.
4. **The bots play as a returning player** (`RunsPlayed = 1`, no last boss). Otherwise every bot run would be a first run and meet only SHELL KING + MIMIC. Unlocks are unchanged, since they come from achievements only. The default `RunDifficultyThresholdTests` (800 runs) uses this too and still passes.
5. **Shell-stopped hits** are a `Hit` / `ProjectileHit` with Value 0 and `Variant = 1`, not a new event type. That is how they keep the normal hit cue. MIMIC's "copied" event fires on the first active tick: spawn-hook events are not shown by the view.
6. **MAGNET's pull strength** uses `MatchConfig.MaxSpeed` (the "normal max speed"); the clamp uses the ball's own normal cap. It pulls every non-boss ball (in a Run, the player).
7. **No-repeat with two bosses per slot** means runs alternate. The seed decides only when no last boss is known.
8. **The Codex also records a boss met through `-bbForceBoss`.** The spec only excludes the forced boss from the last-boss history.
9. **`RunTuning.BossHp` / `BossTraits`** are kept but no longer used by the generator (tests and old sweeps reference them). The old Explicit `RunDifficultySweep` that edits them no longer changes bosses.
10. **Untouched on purpose:** `RunController.BossArtEnabled` stays off (body art exists for Shell King and Mimic only); `BossLookFor` now uses the boss id. The next-goal title "BEAT SHELL KING" (boss1) is unchanged, although MAGNET in slot 1 also counts. The first run always meets SHELL KING.
11. **Tuning moved WARDEN's first step to 6 s.** The hint "WALLS CLOSE EVERY 8S" still matches the cadence after it.
12. **Stale Unity lock file.** The first EditMode run stopped on a compile error, which I fixed. Unity left a stale `Temp/UnityLockfile` behind, not held by any process (checked with an exclusive open). It was not deleted; the next Unity runs worked normally.
13. **One cleanup command** in my own output folder targeted a file that did not exist yet. Nothing was deleted.
14. **EditMode rewrote** `docs/claude-runs/trace-unity-*.txt`: those traces include the Rules number.
